上游固定为 PX4 `v1.17.0`，提交 `d6f12ad1c4f70ad3230afd7d86e971421e02fef4`。分支从该提交创建，不改仓库默认分支，不混入 `main` 的后续改动。完整基线记录见 [baseline.json](baseline.json)。

## 已有代码

`src/lib/indi/IndiControl.{hpp,cpp}` 是无 uORB、无 ROS、无堆分配的固定尺寸 C++ 内核。当前实现是**归一化力矩接口下的对角效能特例**，不是两篇论文的电机转速控制律逐式复现。`src/modules/mc_rate_control/IndiShadow.*` 管理传感器消息、参数事务、时间检查、影子状态和日志。`msg/IndiRateStatus.msg` 已注册到消息构建列表，所有量明确单位和语义。

宿主仅增加三个调用点：构造、参数快照、以及原有 PID 力矩发布之后的影子更新。PID、偏航低通、电池缩放、推力先于力矩的发布顺序、控制分配器和输出安全链不被替换。结构检查可移除这些新增点并恢复**与上游完全相同的 Git blob SHA**。这只证明所检查源代码未被顺带改写，不证明额外 CPU、栈和日志负担不会影响调度。

效能参数 `MC_INDI_GR/GP/GY` 和模型时间常数 `MC_INDI_TAU` 默认零，表示未辨识。必须提供自己的标定值才能产生有效数值候选；不要把测试用参数当作实飞调参。所有新参数只在收到当前周期的未解锁状态后成组生效；飞行中参数更新只暂存。

## 重跑验证

主机需要 CMake、C++14 编译器、Python 3、NumPy。运行：

```sh
bash Tools/indi/run_checks.sh
```

脚本先编译数学库，再并行启动 C++、数学反例和 PX4 结构契约三个检查进程。结果保存在 `build/indi-host/`。当前记录为 14 组 C++ 检查、10 个数学检查、5 个结构检查通过；它们不等于 PX4 SITL、目标板固件、硬件在环或实飞验证。

完整仓库、子模块和 PX4 工具链齐备后，应另外运行 `make px4_sitl_default`，再使用确认过的板级目标构建。当前没有目标飞控板、电调、机架参数或 ULog，因此没有冻结飞行增益、传感器发布率或电机模型，也没有给出可直接刷写的固件。

## 一个重要的数学审查发现

2018 论文附带的 2023 勘误，按其印刷公式直接代入 `K_eta=21.4`，得到的极点不等于文字列出的极点；以有效小角度增益 `21.4/2` 代入则吻合。可能涉及四元数向量增益与角度增益的不同口径。文档与测试保留两套计算，**不把推测当作已经确认的勘误修复**。

论文的 RPM 反馈条件、归一化力矩的标度、完整滤波链以及执行器实际状态尚未在目标平台证明一致。因此，本分支特意不将“能算出有限数值”升级成“可以控制飞机”。接管的工程设计与待修改位置已经写入计划，下一阶段的重点是完善并验证这些接口，而不是增加一个绕过检查的开关。
