# 对抗检查与验证记录

记录日期：2026-09-22。对象：本分支 P0 数学库及只读宿主接入。**通过下面的检查，不代表获准接管飞控，也不等于两篇论文控制器的实机复现。**

## 检查方式与独立性

`Tools/indi/run_checks.sh` 先用 CMake 编译 C++14 内核，再同时启动三个独立进程：C++ 输入/状态检查、Python 数学反例检查、Python PX4 静态契约检查。三条轨道从实现、方程和接口三个角度尝试否定结论；每条轨道都要求退出码为零。这里的“并行”指实际并发执行的测试进程，**不是多名独立研究者或独立模型的同行评审**。测试本身及本文也需要外部复核。

测试执行环境为 GNU C++ 14.2.0，启用 `-Wall -Wextra -Werror -pedantic -fno-exceptions -fno-rtti` 和 AddressSanitizer、UndefinedBehaviorSanitizer。主机算术环境不等于 ARM/NuttX 的优化选项、实时调度或浮点行为。

随机测试固定种子，便于复现。C++ 长序列含 20,000 次有限输入检查及 4,999 次不等 dt 的新增滤波代数检查；Python 包含 2,000 组全矩阵残差检查、2,000 组 Lyapunov 不等式检查和 200 次旋翼置换检查。随机测试不是连续参数域证明，新增两级滤波的代数检查也不是整条 PX4 滤波路径的相位匹配证明。

一次完整重跑命令：

```sh
bash Tools/indi/run_checks.sh
```

输出分别在 `build/indi-host/core-results.txt`、`math-results.txt`、`contract-results.txt`。这些日志描述测试，不是飞行记录。严格验收时保留源码提交、编译命令、依赖版本和原始结果，不只保存“PASS”截图。

## 检查发现及处置

### OPEN-MATH-01：勘误公式与所列极点的增益口径

第一轮测试曾假设：把 2023 勘误文字中的 `K_eta=21.4` 直接代入更正传递函数，应当复现列出的极点。该测试失败。核查后发现，使用 `21.4/2` 的有效小角度增益才能吻合。修订后的测试**同时验证两套数值和不吻合事实**，不把第一轮失败删除后宣称源文献无问题。四元数向量到小角度的二分之一是合理解释，但作者的确切增益命名仍未获得独立确认。详见理论文档第 8 节。

本阶段保留 PX4 原姿态控制，内环使用角速度误差到角加速度的增益，故没有把这组姿态增益直接植入固件。该问题保留为开放项，不能以测试变绿当作已经解决文献歧义。

### FIXED-TIME-01：参数应用不能采用过期解锁状态

早期设计打算在参数通知时直接判断宿主缓存的 armed 状态，可能发生参数通知先于本周期控制模式更新的次序问题。现在参数通知只保存快照，影子 `update()` 收到当前宿主控制模式后才在 `!armed` 时应用整组配置。结构测试锁定这个顺序。真正的跨主题原子时序仍需要目标板检查；当前源码保护不能代替它。

### BLOCK-MODEL-01：请求力矩不是实际执行力矩

当前一阶代理由上一条 PID 最终归一化力矩请求驱动。未纳入控制分配、输出驱动、电机非线性和实际命令发布时间的全部影响。因此即使代理输出有限，`FLAG_MODEL_UNQUALIFIED` 仍永久置位。未来必须用经过时间关联的实际分配/输出信息，以及 RPM 或经验证观察器更新。

### BLOCK-FILTER-01：相同新增滤波器不能消除上游不一致

PX4 角加速度已包含原地处理的角速度滤波链及微分低通。给它和输入模型再加相同两级滤波器，不会自动使总传递函数相同。当前 `FLAG_FILTER_UNQUALIFIED` 永久置位；新增滤波器测试仅保证当前库代码按声明的递推式工作。

### BLOCK-ALLOC-01：慢状态、归一化和饱和

当前分配状态有最小 5 ms 发布间隔；旧残差不能直接与新请求相减得到“当前实现输入”。分配前后裁剪、trim 和 scale 都有专门代数反例。本阶段只记录饱和提示，尚未增加全速、带序号的反馈主题，不能进行控制接管。
